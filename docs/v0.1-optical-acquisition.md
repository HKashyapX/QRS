# v0.1 Optical Acquisition

## Scope

v0.1 removes exact hand alignment as a requirement without changing the transport, fountain code,
or binary optical alphabet. The receiver:

1. downsamples camera luminance and calculates an Otsu threshold;
2. finds bright connected components and scores plausible four-corner frames;
3. tracks and exponentially smooths the best quadrilateral;
4. maps cell centres through a projective square-to-quadrilateral transform;
5. averages nine samples inside each cell; and
6. rejects phase A/B pairs when their normalized corner movement is too large.

The existing manual region-of-interest sampler remains available as a fallback. The first detector
intentionally uses the sender's continuous white quiet zone instead of adding a new dependency. If
real-device tests show that component detection is insufficient, the next detector candidate is a
gradient/line-based quad extractor modelled on AprilTag and compiled to WebAssembly.

## Acceptance gates

- Complete the 23-byte, 1 KB, and 10 KB test ladder without holding either device in a fixed pixel
  alignment box.
- Maintain acquisition through ordinary hand tremor and at least a moderate oblique view.
- Record tracked/missed frames, marker locks/failures, geometry rejects, valid/rejected pairs, and
  recovered symbols.
- Preserve byte-for-byte output validation and the manual fallback.

No reliability percentage is claimed before a device matrix exists. A useful first matrix is at
least three camera devices, three displays, two browsers, three view angles, and three lighting
conditions.

## Primary references to study and borrow from

| Source | What QRS should borrow | What QRS should not copy blindly |
|---|---|---|
| [AprilTag paper](https://april.eecs.umich.edu/pdfs/olson2011tags.pdf) and [BSD-2-Clause implementation](https://github.com/AprilRobotics/apriltag) | Gradient segmentation, line fitting, quad extraction, pose stability, benchmark discipline | Its tag payload and family design; QRS already has temporal data framing |
| [OpenCV.js tutorials](https://docs.opencv.org/4.13.0/d0/d84/tutorial_js_usage.html) | A later WASM path for contour/line detection with explicitly reused matrices | Per-frame `cv.Mat` allocation and an unpinned CDN dependency |
| [OpenCV perspective transforms](https://docs.opencv.org/4.10.0/dd/d52/tutorial_js_geometric_transformations.html) | Four-point homography and normalized warping | Assuming a homography also fixes blur, exposure, or rolling shutter |
| [PixNet](https://people.csail.mit.edu/nabeel/pixnet-mobicom10.pdf) | Display-camera channel model: perspective, blur, ambient light, calibration and measured BER | Its full spatial-frequency/OFDM PHY before QRS has a stable baseline |
| [ISO/IEC 23634:2022 JAB Code](https://www.iso.org/standard/76478.html) and [reference project](https://github.com/jabcode/jabcode) | Colour palettes, finder patterns, calibration, symbol sizing, error correction and decoder tests | Treating a static printed-code decoder as a ready-made temporal link |
| [Microsoft HCCB](https://www.microsoft.com/en-us/research/project/high-capacity-color-barcodes-hccb/) | Colour segmentation and the trade between symbol count and physical cell size | Its proprietary barcode format |
| [Display-camera measurement scheme](https://arxiv.org/abs/1501.02528) | BER experiments that control autofocus, vibration, moire and rolling shutter | A universal reliability claim from one phone/display pair |

These sources are training material and design prior art. Code is only reused when its license is
compatible and attribution is retained; otherwise QRS implements the described algorithm
independently.

## Five-colour research track

The proposed alphabet `{black, white, red, green, blue}` has a theoretical maximum of
`log2(5) = 2.322` raw bits per cell, versus one bit for binary. That is an upper bound, not expected
net throughput. Reference cells, colour calibration, symbol packing, and stronger error correction
consume part of the gain.

The first colour experiment should keep the existing 64×64 geometry and transmit known calibration
frames. Classification should use chromaticity or a perceptual colour space after estimating the
captured palette from reference cells; fixed RGB thresholds are not an acceptable design. Measure a
5×5 confusion matrix and symbol error rate across the device matrix before encoding files.

Only after those measurements should QRS compare these candidates:

| Candidate | Raw bits/cell | Main risk |
|---|---:|---|
| Binary black/white | 1.000 | Lowest density |
| Four chromatic/luminance symbols | 2.000 | Palette separation under auto white balance |
| Five proposed symbols | 2.322 | Non-power-of-two packing plus colour confusion |
| Eight JAB-like colours | 3.000 | Higher crosstalk and calibration/ECC cost |

Grid size is a second, independent variable. At a fixed physical square, increasing from 64×64 to
96×96 produces 2.25 times as many cells but makes every cell one third narrower. v0.1 therefore
stabilizes acquisition first; a later adaptive-density mode can select the largest grid whose
observed cell contrast and blur margin pass a declared threshold.
