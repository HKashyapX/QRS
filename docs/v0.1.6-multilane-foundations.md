# QRS v0.1.6 Multi-lane Foundations

## Purpose

v0.1.6 prepares the working single-lane v0.1.5 implementation for spatial multiplexing without
changing the visible optical layout. The physical two-matrix experiment belongs to v0.2.x; this
milestone establishes the protocol and software boundaries needed to conduct that experiment
without duplicating camera capture or recovery state.

## Implemented foundation

- The existing 16-bit frame flags field now carries a zero-based lane ID and lane count.
- Legacy flags value zero remains lane 0 of one, preserving the v0.1.5 byte representation.
- Lane metadata is covered by the existing frame CRC-32C.
- A session router enforces one lane count and one global symbol-ID namespace per session.
- Symbols received from different lanes enter the same fountain decoder and duplicate filter.
- Each browser optical lane owns its own reusable sample buffer and ordered A/B phase pairer.
- Camera capture and envelope acquisition are separated from per-lane perspective sampling.
- A shared projective envelope can be divided into row/column lane quadrilaterals.
- Receiver diagnostics report configured lanes, active session lanes, and routed frames per lane.

The sender intentionally emits `{laneId: 0, laneCount: 1}` in v0.1.6. Its encoded flags remain
`0x0000`, so this release should behave optically like v0.1.5 during two-device testing.

## Compatibility and safety rules

- Lane count is fixed when the first valid manifest binds a session.
- Lane ID must be smaller than lane count; at most 16 lanes can be represented.
- Reserved flag bits must be zero when lane metadata is interpreted.
- A new valid manifest may bind a new session; non-manifest frames cannot create a session.
- One unreadable lane must not invalidate symbols already accepted from another lane.
- Lane identity does not alter fountain-code dependency generation.

## Validation

Automated tests cover:

- zero-flag compatibility;
- two-lane flag round trips and invalid metadata rejection;
- independent optical-lane sample buffers and phase-pairing state;
- projective subdivision of one envelope into multiple lane quadrilaterals;
- session routing and lane-count consistency; and
- reconstruction from source symbols split across two lane identities.

The physical v0.1.5 test ladder remains applicable because the deployed layout is still one matrix.
Any v0.1.6 regression in marker lock, valid-pair rate, completion, or output bytes blocks v0.2.

## v0.2 entry gate

The first dual-lane prototype should add a composite portrait envelope containing two vertically
stacked matrices. It must reuse one camera image and one outer-envelope transform, then sample and
pair each derived lane independently. The initial acceptance target is at least 1.6 times the
single-lane goodput without exceeding the device processing budget or reducing completion
reliability.
