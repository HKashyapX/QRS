# QRS v0.1.4 Tail and Motion

## Measured reason for this revision

The first v0.1.3 mobile run met the hot-path goals. Average processing fell from 38.8 ms to 21.0 ms,
processing load fell from 884 to 545 ms/s, marker lock reached 70.3%, and valid-pair rate rose from
0.50 to 4.39 frames/s. The receiver reconstructed all 156 source symbols from a roughly 40 KB
object, but the final few percent took disproportionately long.

Tracking itself was not the motion bottleneck: 4,066 of 4,086 camera frames had a tracked quad,
only 20 acquisition frames were missed, and no pair was rejected for geometry. The yellow overlay
was misleading because it represented the result of the latest marker classification rather than
whether the outer frame was still tracked.

## Changes

- Keep the balanced two-systematic/one-repair stream, change repair frames to deterministic dense
  rows, and add GF(2) Gaussian elimination when the
  unresolved tail has at most 64 symbols and enough equations have accumulated. Fast belief-
  propagation peeling remains the normal path; elimination closes full-rank stopping sets that
  peeling alone cannot solve.
- Add a deterministic 156-symbol test with 40% loss and short loss bursts. It must reconstruct in
  fewer than 700 logical frames.
- Report accepted source versus repair frames and unique versus duplicate encoding symbols. These
  counters expose whether future slow tails come from channel loss, repeats, or ineffective repair
  equations.
- Treat the green guide as a tracking indicator, not a per-camera-frame decode indicator. A 500 ms
  tracking hold absorbs brief detector misses, while text reports whether a clean optical phase was
  decoded in the last 600 ms.
- Move manual alignment size and minimum cell contrast into an advanced field-test section. The
  384 px box is only a manual fallback and has no effect while automatic tracking is enabled.
- Restore the marker-contrast minimum sentinel correctly when resetting diagnostics.
- Label the 67 ms sender setting as milliseconds per phase. Since every logical frame needs A and
  B phases, its ideal ceiling is about 7.46 logical frames/s, not 67 Hz.

## Why the last symbols are slower

The receiver can solve systematic symbols immediately, so early progress is steep. Near completion,
the unresolved set contains source symbols whose observations were erased. Repair equations can be
independent yet contain no degree-one row, which stalls belief-propagation peeling even when the
system is already solvable. The bounded elimination pass solves that case. Because the optical
channel is simplex, the sender still receives no missing-symbol list; a statistical tail remains
when the collected system is genuinely rank-deficient.

## Next physical comparison

Repeat the same approximately 40 KB file at 67 ms per phase, with the same devices, distance, and
brightness. Record total completion time and the time at which progress first reaches 90%. Compare:

- valid logical frames/s;
- accepted source/repair frames;
- unique/duplicate data symbols;
- time from 90% to completion;
- marker locks/failures and top errors;
- processing average/load.

The change is successful if the final 10% occupies a smaller fraction of the transfer without a
large fall in valid-pair rate. Physical performance remains device- and channel-dependent.
