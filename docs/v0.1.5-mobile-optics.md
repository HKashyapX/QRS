# QRS v0.1.5 Mobile Optics

## Measured reason for this revision

The v0.1.4 desktop-to-phone path removed the decoder tail, but the first phone-to-phone test was
much slower and the receiving phone did not autofocus reliably. A phone display produces a
physically smaller 76×76-cell optical envelope than a laptop, so distance has a larger effect on
the number of camera pixels representing each cell. Phone OLED PWM, rolling shutter, focus, and
exposure can then reduce valid A/B pairs even when geometry tracking remains locked.

## Changes

- Request continuous focus when the camera track exposes it.
- Use a square 640×640 receiver sampling surface rather than 640×480, allowing up to 33% more
  linear optical-envelope resolution when the matrix fills the preview.
- Request one point-focus sweep at the detected matrix centre after the first geometry lock; manual
  tap-to-focus remains available for refocusing.
- Tapping the preview maps the touched point through the cover-crop transform into normalized camera
  coordinates and requests a point-of-interest autofocus/auto-exposure/white-balance sweep.
- Prefer single-shot focus for a tap, fall back to continuous focus, then fall back to a centre sweep
  when the browser exposes focus mode but not point-of-interest control.
- Show a temporary blue focus reticle and report focus capabilities, requests, successes, failures,
  and the last applied focus state.
- Measure the tracked QRS envelope in camera pixels per optical cell. Values below roughly four
  pixels per cell are flagged by the test procedure as a distance/physical-size problem.
- Report sender display pixels per cell, actual phase rate, late phase count, and maximum scheduling
  lateness so mobile rendering throttling can be separated from camera decoding loss.
- Report marker-lock percentage and an explicit current optical-bottleneck classification.
- Request a screen wake lock while transmitting so a phone does not dim mid-transfer.

## Phone-to-phone comparison

Use the same file and phones for two runs: first at 100 ms per phase, then at 67 ms per phase. Tap
the centre of the matrix after starting the receiving camera. Record total time plus the complete
receiver diagnostics and sender phase-rate line. The next change should be chosen from evidence:

- low camera pixels/cell: physical matrix size or a lower-density optical profile;
- high sender lateness: mobile rendering schedule;
- adequate cell size but marker/contrast errors: exposure, PWM, or marker sampling;
- healthy optical rates but slow completion: transport/FEC behavior.

The supplied v0.1.4 phone-to-phone trace locked geometry on all 754 sampled frames but recognized
orientation on only 27 (3.6%), producing 0.06 valid pairs/s. Its accepted marker frames averaged
137 contrast, so lowering the 12-level marker floor again would not address the dominant failures
and would weaken rejection of incorrectly sampled frames. This revision therefore improves spatial
sampling and focus rather than relaxing integrity checks.
