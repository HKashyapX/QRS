# QRS v0.1.3 Acquisition Hot Path

## Measured reason for this revision

The first v0.1.2 physical run improved valid-pair rate from 0.36 to 0.50 frames per second and
recovered 19 pairs on a later B observation, confirming that retained phase-A candidates work.
However, average processing rose to 38.8 ms at 22.8 camera frames per second: 884 ms of work per
second. Marker lock fell to 996 of 2,332 camera frames, with 1,022 failures attributed to the fixed
orientation-contrast floor. The decoder also rejected 247 pairs because one low-contrast data cell
was enough to discard an otherwise potentially valid frame.

## Changes

- Inline homography projection in the 64×64 sampling loop instead of allocating a point object for
  each of its 20,480 luminance samples.
- Cache normalized five-point sampling coordinates and reuse the 4,096-byte sampled-cell buffer.
- Refresh the diagnostic DOM at 4 Hz instead of on every camera callback.
- Record capture, detector, sampler, classifier, and pair-decoder timing separately.
- Lower the marker luminance-range floor from 28 to 12 while retaining the marker error budget,
  phase-pilot validation, frame structure checks, and CRC-32C.
- Permit up to 8% weak differential data cells when their sign still yields a CRC-valid frame.
  Heavily transitional frames continue to fail before frame parsing.
- Force early reacquisition after three consecutive marker failures rather than six.

## Integrity boundary

Weak optical evidence is never accepted as file data on its own. A candidate still needs a valid
orientation, phase pilot, header bounds, and CRC-32C before entering the LT decoder. The relaxed
contrast rules therefore convert uncertain camera samples into erasures when their inferred bits
are wrong; they do not bypass frame integrity.

## Next physical test

Use the same phone, display, 7 KB file, 150 ms phase duration, distance, and brightness as the
v0.1.2 run. Compare these fields:

- processing average and processing load;
- hot-path capture/detect/sample/classify/pair averages;
- marker lock percentage and the ranked error list;
- valid frames per second and observed-pair survival;
- resolved symbols and estimated resolved goodput.

The immediate gate is average processing below 30 ms, processing load below 650 ms/s, marker lock
above 60%, and at least 1.0 valid frame per second. These are physical acceptance targets, not
claims made by the automated tests.
